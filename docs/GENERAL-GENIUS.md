# General Genius Model

Status: v0.1 draft

## Core Formula

```txt
Mastery = Capability x Evidence x Taste x Stewardship x Compounding
```

If any term is zero, the system becomes weak:

- capability without evidence is a claim
- evidence without taste becomes bureaucracy
- taste without stewardship becomes risky ego
- stewardship without compounding becomes maintenance
- compounding without capability becomes scale theater

## Ten Design Laws

### 1. Progress Must Change Ability

If a rank does not change what someone can make, understand, protect, publish, or lead, it is decoration.

### 2. Evidence Beats Confidence

The system should ask "what proves it?" before it asks "how high is the level?"

### 3. Skills Need Context

A skill is only real when it names:

- inputs
- procedure
- output
- gates
- failure modes
- evidence

### 4. Agents Need Loadouts

An agent is not a fixed identity. It is a runtime that equips:

- skills
- tools
- memory
- permissions
- constraints
- evals
- handoff rules

### 5. Worlds Need Memory

A world that cannot remember is content. A world that remembers becomes a place.

### 6. Products Need Proof

A product should carry:

- source
- license
- version
- evidence
- support boundary
- upgrade path

### 7. Power Needs Cost

In games, powers need costs. In agent systems, autonomy needs gates. In creator systems, publishing needs stewardship.

### 8. Repair Is Progress

Fixing drift, catching risk, restoring continuity, and protecting private memory are not chores. They are mastery events.

### 9. Plain Language At The Boundary

Use clear platform names at system boundaries:

- Mastery Engine
- Skill Tree
- Trial
- Loadout
- Ledger
- Reward

Use mythic language inside Arcanea experiences:

- Epoch Forge
- Luminor Academy
- Gate Trial
- Citadel
- Relic

### 10. The System Should Teach Itself

Every completed artifact should make the next artifact easier:

- templates improve
- examples accumulate
- agents rank up
- skills verify
- ledgers record
- products become reusable

## The Genius Loop

```txt
Create -> Evaluate -> Remember -> Improve -> Package -> Teach -> Repeat
```

This loop works for:

- humans
- agents
- worlds
- skills
- games
- products
- communities

## Evaluation Questions

Use these when a progression system feels fuzzy:

- What new capability appears?
- What evidence proves it?
- What did the system learn?
- What can be reused?
- What risk was reduced?
- What can now be shipped?
- What should not be automated yet?
